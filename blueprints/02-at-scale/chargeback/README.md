# Chargeback lab: CUR 2.0 + Kubecost showback (runbook)

Lab for the PMI "CloudBees CI - Chargeback Modeling & Dashboards" plan (decision D4, lab-first D5).
It runs on the `02-at-scale` blueprint in a CloudBees AWS account, with fictional teams only.
Test results are recorded in the engagement plan (`chargeback-plan.md`, Section 5.5).

## What it deploys

| File | Resources |
|---|---|
| `../chargeback.tf` | CUR 2.0 export (hourly, Parquet, resource IDs) to a private S3 bucket; Glue database and crawler (every 6 h); Athena workgroup with a 1-day results bucket; Kubecost 3.3.1 (EKS bundle) with a Pod Identity role scoped to these resources; an unpinned gp3 storage class for Kubecost |
| `../chargeback-export.tf` | Daily `showback-export` CronJob (01:30 UTC, re-exports the last 3 days), a private S3 bucket for its output, a read-only mount of the EFS root, a Pod Identity role with CUR read access (same as Kubecost) and `s3:PutObject` on `showback/*` only; the CUR selector (`cb_cur_selector`) |
| `../chargeback-grafana.tf` | Glue database and two tables over the export (`report_by_controller`, `showback_allocated`; partition projection, no crawler), Athena workgroup `<name>-showback`, read-only Pod Identity role for Grafana, Athena data source and dashboards as ConfigMaps for Grafana's sidecars |
| `../k8s/kube-prom-stack-values.yml` | Changed: installs the `grafana-athena-datasource` plugin; points two blueprint dashboard URLs that return 404 upstream to this branch (Grafana was in a crash loop because of them) |
| `../k8s/kubecost-values.yml` | Kubecost values: public ECR images, 16-day retention, 32Gi aggregator volume, network costs off, no `keep` annotation on volumes |
| `showback_export.py` | Export logic (standard library only) |
| `grafana/showback-platform.json`, `grafana/showback-team.json` | Grafana dashboards (platform owner; one team with a controller picker) |
| `cur_external.sh` | Athena query for the cluster's CUR costs that Kubecost does not see, one CSV per day |
| `mapping.csv` | Controller -> team -> cost centre (the only file to edit to add a team) |
| `cur2-query.sql` | CUR 2.0 column list (114 columns, generated by the AWS console) |

Deploy with the blueprint: `terraform plan` then `terraform apply` in `blueprints/02-at-scale`.

## Allocation key (labelling standard)

No pod template change is required. CloudBees CI sets these labels itself (verified in the lab):

| Pod | Label | Example |
|---|---|---|
| Managed controller | `tenant=<controller>` (also `com.cloudbees.cje.tenant`) | `tenant=team-b` |
| Agent pod (any namespace) | `cloudbees.com/master=<controller>` | `cloudbees.com/master=team-a` |
| Operations Center | `com.cloudbees.cje.tenant=cjoc` | shared platform |

Kubecost returns label keys sanitised (`cloudbees_com_master`, `com_cloudbees_cje_tenant`). The export
accepts both forms.

Optional, for the Kubecost UI only: grouping by one label needs the same key on agent pods. Set
`podLabels` on each Kubernetes cloud of a controller (CasC or Groovy), for example
`tenant=<controller>`. Verified on `team-b` (runtime change through the script console). The export does not need this.

## Add or change a team

1. Add a row to `mapping.csv` (`controller_id` must equal the controller name).
2. `terraform apply` (updates the `showback-export` ConfigMap).
3. Pods of a controller that is not in the mapping are reported as `__unallocated__`, never spread.

## Run and read the export

- Run now: `terraform output -raw showback_export_run` prints the command. Each run re-exports the
  last 3 days (UTC) and overwrites them, because Kubecost reconciles with CUR 12-36 h after usage.
  To export one other day, add env `DAY=YYYY-MM-DD` to the `cur-external` and `export` init containers.
- Output: `s3://<name>-showback-<account>/showback/date=YYYY-MM-DD/`
  - `showback-direct.csv`: one row per controller and resource class (`controller_compute`,
    `controller_storage`, `agent_compute`, `shared_platform`, `shared_idle`, `external_<service>`,
    `unallocated`). Every mapped controller has a row, so a hibernated one shows 0.
    `cur_included=True` means the day's CUR costs were added; `False` means Kubecost list prices only.
  - `showback-allocated.csv`: shared platform, idle and external cost spread by direct cost (`SHARE_RULE=proportional`)
  - `report-by-controller.csv`: **the per-controller report**, one line per controller (compute, storage,
    agents, shared share, total, % of total); unallocated cost has its own line
  - `controller=<id>/showback.csv`: that controller's rows only. Grant a team read access to its own
    prefix (`showback/date=*/controller=<id>/*`) to show it only its own cost.
  - `allocation-raw.json`: Kubecost response, unchanged; `cur-external.csv`: CUR rows used;
    `efs-usage.tsv`: `du -sk` per EFS access point, taken at export time
- Unallocated share is printed in the job log, e.g. `unallocated=0.0000 (0.0%)`.

## Dashboards

**Grafana (the showback dashboard).** Two dashboards read the export through Athena, so they show the
same figures as the S3 report (bill-reconciled, shared cost spread):

- `CloudBees CI showback - platform` (`/d/showback-platform`): total, teams' own cost, shared platform
  cost, unallocated %, cost per controller, daily cost by component, per-controller table.
- `CloudBees CI showback - team` (`/d/showback-team?var-controller=<id>`): one controller's totals,
  daily cost by component, daily rows.

URLs: `terraform output grafana_showback_dashboards`. The export copies the two reports to
`showback/tables/<table>/date=YYYY-MM-DD/` for the Glue tables. In the lab Grafana is on a public load
balancer with the admin password; for real cost data use an internal load balancer and SSO, and give
teams their own dashboard folders if they must not see each other's cost.

**Kubecost saved reports (supplement for engineers).** Created in the Kubecost UI (Monitor > Allocations,
then Save Report); stored in Kubecost's persistent config volume, not in this repository:

| Report | Allocations view |
|---|---|
| Showback - controllers by tenant label (30d) | `?window=30d&agg=label%3Atenant` |
| Showback - agent pods by controller (30d) | `?window=30d&agg=label%3Acloudbees_com_master` |
| Showback - namespaces incl. platform (30d) | `?window=30d&agg=namespace` |
| Showback - top pods for right-sizing (7d) | `?window=7d&agg=pod` |

Kubecost figures lack the CUR-only costs, so use them for drill-down and right-sizing, not as showback totals.

## Costs from CUR (outside Kubecost)

Kubecost covers node compute and volumes. The export adds, from CUR through Athena, the cluster's other
costs as `external_<service>` shared rows: EKS control plane (and extended support), NAT gateway, load
balancers, node root volumes, CloudWatch logs, and the lab's own S3/Glue/Athena. EC2 instance compute and
EBS volumes already counted as PVs are excluded, so nothing is counted twice. The EFS bill replaces
Kubecost's EFS volume cost and is split by `du` share.

The cluster's resources are selected by `cb_cur_selector` in `../chargeback-export.tf`. For PMI, replace it
with one cost allocation tag activated by the payer account: `resource_tags['user_<tag>'] = '<value>'`.
The lab account cannot activate tags, so its selector combines names and two tags that are already active.
Lab result for 2026-11-11: showback total 24.06 USD, CUR for the cluster's resources about 24.03 USD.

## Known limits

- Kubecost prices an EFS volume by its requested size, which is nominal for EFS (lab: 20Gi requested,
  0.23 GiB used). Use `efs_used_gib` from `du` for EFS showback; `du` time grows with file count.
- EFS volumes expose no `kubelet_volume_stats_used_bytes`; EBS volumes do.
- CUR has no backfill and the first delivery can take up to 24 h. Until the crawler creates
  `<db>.cur2_data`, Kubecost logs `TABLE_NOT_FOUND` and shows list prices, not the bill.
- Split cost allocation data is off: only payer or standalone accounts can opt in (console only).
- History: Kubecost keeps about 15 days; the daily S3 export is the long-term record.
- EFS cost is mostly throughput (lab: 1.25 USD data access vs 0.002 USD storage per day). Splitting it by
  `du` share is a proxy; AWS gives no per-access-point throughput.
- `SHARE_RULE=proportional` puts all shared cost on the controllers that ran that day: on 2026-11-12 the
  hibernated `team-b` paid 0 and `team-a` paid the whole platform. A flat or hybrid rule avoids this (plan Q6).
- The lab selector misses volumes of Karpenter nodes (no unique tag); a cluster tag at PMI covers them.

## Tear down

`terraform destroy` removes everything, including the S3 buckets (`force_destroy`) and Kubecost
volumes. The CUR export stops when its resource is destroyed.
