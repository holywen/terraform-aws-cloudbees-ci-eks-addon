# Chargeback lab: CUR 2.0 + Kubecost showback (runbook)

Lab for the PMI "CloudBees CI - Chargeback Modeling & Dashboards" plan (decision D4, lab-first D5).
It runs on the `02-at-scale` blueprint in a CloudBees AWS account, with fictional teams only.
Test results are recorded in the engagement plan (`chargeback-plan.md`, Section 5.5).

## What it deploys

| File | Resources |
|---|---|
| `../chargeback.tf` | CUR 2.0 export (hourly, Parquet, resource IDs) to a private S3 bucket; Glue database and crawler (every 6 h); Athena workgroup with a 1-day results bucket; Kubecost 3.3.1 (EKS bundle) with a Pod Identity role scoped to these resources; an unpinned gp3 storage class for Kubecost |
| `../chargeback-export.tf` | Daily `showback-export` CronJob (01:30 UTC), a private S3 bucket for its output, a read-only mount of the EFS root, a Pod Identity role allowed only `s3:PutObject` on `showback/*` |
| `../k8s/kubecost-values.yml` | Kubecost values: public ECR images, 16-day retention, 32Gi aggregator volume, network costs off, no `keep` annotation on volumes |
| `showback_export.py` | Export logic (standard library only) |
| `mapping.csv` | Controller -> team -> cost centre (the only file to edit to add a team) |
| `cur2-query.sql` | CUR 2.0 column list (114 columns, generated by the AWS console) |

Deploy with the blueprint: `terraform plan` then `terraform apply` in `blueprints/02-at-scale`.

## Allocation key (labelling standard)

No pod template change is required. CloudBees CI sets these labels itself (verified in the lab):

| Pod | Label | Example |
|---|---|---|
| Managed controller | `tenant=<controller>` (also `com.cloudbees.cje.tenant`) | `tenant=team-b` |
| Agent pod (any namespace) | `cloudbees.com/master=<controller>` | `cloudbees.com/master=team-a` |
| Operations Center | `com.cloudbees.cje.tenant=cjoc` | shared platform |

Kubecost returns label keys sanitised (`cloudbees_com_master`, `com_cloudbees_cje_tenant`). The export
accepts both forms.

Optional, for the Kubecost UI only: grouping by one label needs the same key on agent pods. Set
`podLabels` on each Kubernetes cloud of a controller (CasC or Groovy), for example
`tenant=<controller>`. Verified on `team-b` (runtime change through the script console). The export does not need this.

## Add or change a team

1. Add a row to `mapping.csv` (`controller_id` must equal the controller name).
2. `terraform apply` (updates the `showback-export` ConfigMap).
3. Pods of a controller that is not in the mapping are reported as `__unallocated__`, never spread.

## Run and read the export

- Run now: `terraform output -raw showback_export_run` prints the command. The default day is yesterday (UTC).
  To export another day, add env `DAY=YYYY-MM-DD` to the `export` init container.
- Output: `s3://<name>-showback-<account>/showback/date=YYYY-MM-DD/`
  - `showback-direct.csv`: one row per controller and resource class (`controller_compute`,
    `controller_storage`, `agent_compute`, `shared_platform`, `shared_idle`, `unallocated`)
  - `showback-allocated.csv`: shared platform and idle cost spread by direct cost (`SHARE_RULE=proportional`)
  - `allocation-raw.json`: Kubecost response, unchanged; `efs-usage.tsv`: `du -sk` per EFS access point
- Unallocated share is printed in the job log, e.g. `unallocated=0.0000 (0.0%)`.

## Known limits

- Kubecost prices an EFS volume by its requested size, which is nominal for EFS (lab: 20Gi requested,
  0.23 GiB used). Use `efs_used_gib` from `du` for EFS showback; `du` time grows with file count.
- EFS volumes expose no `kubelet_volume_stats_used_bytes`; EBS volumes do.
- CUR has no backfill and the first delivery can take up to 24 h. Until the crawler creates
  `<db>.cur2_data`, Kubecost logs `TABLE_NOT_FOUND` and shows list prices, not the bill.
- Split cost allocation data is off: only payer or standalone accounts can opt in (console only).
- History: Kubecost keeps about 15 days; the daily S3 export is the long-term record.

## Tear down

`terraform destroy` removes everything, including the S3 buckets (`force_destroy`) and Kubecost
volumes. The CUR export stops when its resource is destroyed.
